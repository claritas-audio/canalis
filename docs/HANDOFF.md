## Decisions taken (2026-11-09)
- Canalis is its own repo in the `claritas-audio` org, next to the private `claritas` and `claritas-site` repos. It depends on `claritas-core` from M3 (git dependency until published).
- A chain is one PipeWire node (capture + playback stream pair in one process callback) and *is* the virtual device. Four types from one mechanism: output, mic, cable, insert (`architecture.md`).
- Chains accept several inputs (summed by PipeWire) and several outputs (copies); chains can feed chains; cycles are refused (#30). Parallel inside a chain is a later slot kind (#31).
- Studio One's console is the model for M7; scenes (#32) may be pulled into v0.1.
- Code conventions: Claritas `docs/code-standard.md` verbatim (not copied here; read it from the Claritas checkout).
- Graph widget: hand-rolled canvas on `egui::Scene`, not `egui-snarl` (0.12 pins egui 0.36; it owns an editable graph where ours is a mirror). ADR 0004.
- Defaults shown are the *effective* ones (`default.audio.*`), not `default.configured.*`: WirePlumber keeps the configured key on an unavailable device (e.g. unplugged headphones) while the effective one stays elsewhere.
- Snapshots: every registry change sets a dirty flag and requests one `core.sync`; the matching `done` publishes a single `Graph`. The GUI gets `ctx.request_repaint()` from the pw thread, so a `pw-link` shows on the next frame.
- Reconnect: a loop timer ticks at 1 s; a core error on `PW_ID_CORE` marks the connection lost and the next tick drops it, publishes `connected: false` and reconnects with backoff 1, 2, 4, 8, 10 s. The same path covers PipeWire being down at start. The timer source cannot be re-armed from inside a callback (pipewire-rs `TimerSource` borrows the loop), hence the permanent tick.

## #43 settings that survive versions, 2026-11-12 (`issue/43-settings-compat`)
